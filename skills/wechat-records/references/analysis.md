# 记录分析

按问题选数据：找通知优先 search 指定群与日期；理解讨论先读小段 history，再补相关上下文；统计活跃度先 stats，不先把全部历史发给模型。

输出分析时说明：账号别名、聊天对象、时间区间、实际读取条数、是否受 limit/缺失分片影响。用时间与发送者给关键结论提供定位；待办应尽量包含负责人、事项、截止时间、原消息依据。不根据单条消息推断对方性格、心理状态或未明说的意图。

当多个同名联系人出现时停止合并，改用唯一 username 查询。遇到分片缺失、上游 failures、无法解压等，保留不完整标记。出现零条消息时查清是范围为空、聊天对象未匹配还是缺库；不要宣称完整记录已读完。

本地数据解密与读取不调用云模型；Codex 对读取内容的分析使用当前模型服务。按用户指定范围读取，导出的完整文件不必全部加入对话。发布示例、测试和截图只用合成数据；不把真实记录、账号路径或密钥放入仓库。
